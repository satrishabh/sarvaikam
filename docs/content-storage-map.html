03 / Data model

The relationships behind a course.

Content database / catalogue
learning_paths [slug PK]
  name · subtitle · description · icon · tone · priority
  │
  ├── learning_path_outcomes
  │     path_slug FK · position · outcome
  └── learning_path_topics
        path_slug FK · topic_slug FK · position
                            │
categories [id PK]       │
  └── topics [id PK, slug UNIQUE] ←┘
        category_id FK · name · summary · level
        └── lessons [id PK]
              topic_id FK · slug · title · step_number
              stage · exclusive · updated_at
              content_object → bucket body
              └── lesson_assets [UUID PK]
                    lesson_id FK · filename · content_type
                    object_name · expected_size
                    generation · ready · created_at

content_documents [name PK: practice]
  content_object → JSON question array

A “course” is a topics row. Paths can share courses. Lessons follow Starter → Intermediate → Advanced → optional Deep Dive, then step number.

Separate database / sarvaikam_reels
reels [slug PK]
  course_slug ── logical link to topic
  lesson_slug ── logical link to lesson
  heading
  content_object → bucket text
  source_name · source_url
  published · updated_at
Reel template
Course → Step → Heading → Content → Source

Course name and step number resolve from the current lesson. Cross-database links are checked by the API. Drafts stay out of the public feed.

Other service-owned data

Auth: users, role_policies, access_audit

Progress: lesson_progress, lesson_bookmarks

These share the main PostgreSQL database in the default deployment. Reels explicitly uses a separate database. Practice answer drafts remain in the learner’s browser.

What links a file to a lesson?

Bucket object
lesson-bodies/abc.md
Contains the actual lesson text.

↕

Database row
lessons.content_object = 'lesson-bodies/abc.md'
Also stores its course, heading, step, level, and access.

Every save uses a fresh object name. Uploading a file does not automatically publish it. Preserve old objects until references and backups are checked.

05 / Direct publishing

Upload, link, verify, publish.

Prepare the body

Write reviewed UTF-8 Markdown or reel text. Include original references; decide the course, step, level, and access.

Upload a new object

Use the Cloud Storage console or gcloud storage cp. Choose a fresh UUID name and confirm success.

Insert the metadata

In the right database, store the exact relative object name. Use lessons for a lesson or the separate reels table for a reel.

Review the result

Open the lesson through the API. Review reels as drafts, then set published=true when ready.

How do I change path priority?

Edit learning_paths.priority: 1 Gen AI, 2 AI / ML, 3 Cloud, 4 Full Stack, 5 Backend, 6 Forward Deployed. Reload Home or Paths. No frontend rebuild is needed.

How do I add a course to a path?

Create a topics row under a category, add its lessons, then add a learning_path_topics row with the path slug, topic slug, and position. Empty courses stay hidden from path sequences.

When does a lesson become visible?

A committed lesson record is available immediately through the API. Lessons currently have no draft field. An exclusive lesson requires the corresponding access. Reels have an explicit draft/published flag.
